# Her 产品准则

现行文档。2026-09-23 由用户拍板建立，吸收奕枢 `docs/PRODUCT.md` 等旧仓库中仍成立的部分。
工程契约（完成判据、任务协调、验收基建）以 `AGENTS.md` 及其指向的 `docs/architecture/`、`docs/guides/` 为准；本文件回答"做成什么样的产品"和"往哪个方向走"。

## 产品简介

2026-09-25 由用户确认。本文件其余部分都要与这一节一致；冲突时以这一节为准并修正其余部分。

**她是什么**：住在你 Mac 上的中文伙伴。叫她就回应。她有名字、有性格、记得你、会聊天，也会在对的时候主动开口。你说一句话，她在后台把几分钟的整段工作做完，不抢你的鼠标键盘，做完如实告诉你做没做成。

**给谁用**：先给用户自己。但不做只有他才能用的设计：不写死路径，也不依赖他这台机器上的特殊配置。

**为什么自己做，而不用现成的**：现成的产品都把你绑在它自家的模型和权限上。她能接入你手上的任何订阅：思考用哪个模型、调度哪些工具（ChatGPT、Claude、Cursor……）都可以换。她的权限也更大：能读写文件、跑命令、操作任何应用。语音暂时用阶跃。Incredible、Today AI 这些产品只作为参考，不跟它们比。

**第一个要做好的**：替你把活交给其他 AI 工具，先接 Claude Code 和 Codex（[验收任务](#验收任务) 1 到 4）。她知道你最近在做什么、看过哪些好案例，所以你说一句，她能替你把要求说得比你自己说的更完整（2026-09-25 补充）。

**底线**：发消息、发邮件、付款、删除这类收不回的操作，先给你看；从不虚报完成。

**不做**：企业和团队功能，也不拼应用集成数量。几小时无人值守的长任务和手机端，以后可能做。

## 一句话

她常驻在你的 Mac 上：叫她就回应，记住你说过的事，能在后台把几分钟的整段工作做完而不抢你的鼠标键盘，并如实说出做没做成。

## 她是谁

- 住在这台电脑里的长期共事者。不是恋人、客服、奴仆，也不是冷工具。
- 名字由用户在首次启动时起。代码与文档里称"她"；`Her` 只是应用名，不是她对用户的自称。
- 说话直接、安静、准确，默认中文。先出声再做事：要她做事时先听到一句受理，但受理只表示接下了，不表示做完，结果以回执为准；能一句说清就一句。不空夸，不撒娇，不客服式热情。
- 不假装有意识，不假装看过没看过的东西，不假装做完没验证的事，不把模型名或供应商当自己的身份。

北极星：增加一个人理解、创造、照顾并参与这个世界的能力，不以剥夺用户的自主权为代价。
不优化消息数、使用时长和打开次数；优化被真实推进的事、被省下的时间、被正确避免的打扰。能力越强，越要少打扰。

## 价值函数

每一项都要有可运行的测量，否则不算标准。目标值是初始值，由用户体验后调整；达不到时如实记录，不改口径。

| 维度 | 测量 | 初始目标 | 2026-09-23 现状 |
| --- | --- | --- | --- |
| 响应延迟 | 用户说完 → 她第一声（真麦克风，p50） | ≤ 1.2 s | 未测；`os` 已有 speech-stop→first-audio 遥测，缺真机数据 |
| 打断延迟 | 用户插话 → 她停止出声 | ≤ 0.5 s | 未测 |
| 虚报完成 | 她口头声称完成、但独立读回不符的次数 | 0 | 受控夹具上成立；真人语音路径未验收 |
| 跨会话记忆 | 下一次会话能用上用户只说过一次的事 | 能 | 无 |
| 打扰控制 | 主动提醒被用户接受的比例；误唤醒每小时次数 | 待定 | 无 |

参照：独立测试中 OpenAI 语音约 1.1 s 回应、1.4 s 停下（见 `out/research/2026-09-23-competitors.md`，本地未入库）。

## 已定的方向（2026-09-23）

| 问题 | 决定 | 含义 |
| --- | --- | --- |
| 默认入口 | 语音优先 | StepFun 实时语音成为默认模式；JEV 文字保留为备用入口 |
| 供应商 | 语音用阶跃，订阅版与开放平台都可（2026-09-25 起只约束语音，见下表「不绑定」） | 哪个端点能可靠调工具就用哪个；Gemini 已于 2026-09-25 删除 |
| 形象 | 先做系统级状态界面，角色形象以后再说 | 先做 `ThinkingOrb` 状态指示；角色形象暂不做 |
| 名字 | 用户首次启动时起名 | 名字存本地，进入人格提示词 |
| 调工具前的第一声（2026-09-24） | 由应用说一句固定受理（如「好，我来。」），不让模型自由说开场白 | 文字由代码固定，与回执走同一条语音路径；只在任务已被接下时说，不声称结果。模型自己的开场白仍按现有契约压制（`StepFunRealtimeSession`），因为它会重复、换声、抢在回执前说完成 |

### 2026-09-25：以 Incredible 为主要参照后的决定

| 问题 | 决定 | 含义 |
| --- | --- | --- |
| 主身份 | 陪伴和做事对等，而且是同一个人 | 声音、性格、记忆是外层，做事是内层；不拆成两条线，每个阶段都用一句用户对她说出口、她边做边沟通完成的[验收任务](#验收任务)来验收 |
| 任务范围 | 几分钟的整段工作 | 不只限于当前窗口的一两步；她做完来汇报 |
| 用户在做什么 | 用户继续用电脑 | 她不抢鼠标键盘：浏览器里用她自己的标签页，桌面应用用后台操作 |
| 操作方式 | 接口优先，点界面兜底 | 应用有可用接口就调接口；没有才读屏幕、点界面 |
| 确认边界 | 对外和不可撤销的先问 | 发消息、发邮件、发帖、付款、删除先给草稿，用户确认后执行；读、查、整理、写草稿直接做 |
| 调用其他 AI 工具（ChatGPT、Cursor） | 由她按情况判断路径 | 用户已经在某个应用会话里、任务依赖那个会话的上下文时，操作那个应用；新开的独立任务（如一次深度调研）走接口 |
| 主要场景 | 浏览器网页；微信；ChatGPT、Cursor 等 AI 工具；以后可能加飞书 | 微信没有开放接口、无障碍信息少，只做只读，排在后面 |
| 第一个要做好的 | 调用其他 AI 工具：替用户去问、指挥 Cursor、盯进度 | 见 `docs/ROADMAP.md` 阶段 4 |
| 给谁用 | 先给用户自己，但不堵死 | 不写死路径、不依赖用户机器上的特殊配置；不做企业和团队功能 |
| 为什么自己做 | 接入用户的任何订阅、不绑定某一家、权限和自由度更大 | 用户原话：「我只是想做一个自己个人用的，所以希望它能够接入我想要的几乎任何订阅，不绑定于某一家，并且有更大的权限、更高的自由度」 |
| 不绑定 | 她做事的大脑和被调度的工具都能换成用户的任何订阅；语音暂时仍用阶跃 | 取代 2026-09-23「供应商只用阶跃」对大脑和工具的约束 |
| 权限 | 放开：读写文件、跑命令、操作任何应用 | 「对外和不可撤销的先问」仍然成立 |
| 陪伴 | 四种行为都要：做事时的沟通（受理、进度、汇报、商量）、记得你、闲聊和情绪、在对的时候主动 | 与做事是同一个人，不拆成两条线 |

### 2026-09-25：把整个项目过一遍后的决定

| 问题 | 决定 | 含义 |
| --- | --- | --- |
| 调用其他 AI 工具，具体做哪一步 | 替用户发指令：用户说要做什么，她整理上下文交给工具；盯进度在后 | 她打包用户的原话、最近在做的事、相关案例和截图，由工具自己展开；汇报时附上交出去的内容 |
| 先接哪个工具 | Claude Code 与 Codex，走命令行 | Cursor、ChatGPT 放后面；验收任务 3、4 改为 Claude Code |
| 她的价值 | 懂用户：知道用户最近在做什么、看过哪些好案例 | 记忆中这两部分随阶段 4 一起做，见 `docs/ROADMAP.md` |
| 默认入口 | 语音重要，但可以晚一点 | 取代 2026-09-23「语音优先」对推进顺序的约束：先用文字入口把事办成，语音暂时停掉（代码里的默认模式不变） |
| Claude Code、Codex 算什么 | 被她调用的外部命令行工具 | 不算第二个推理运行时 |

这三张表只记录方向。截至 2026-09-23，语音默认、起名和 `ThinkingOrb` 状态指示已在代码中落地（证据见 `docs/development/2026-09-23-voice-conversation-quality.md`）；每项落地时按 `AGENTS.md` 的文档同步规则更新对应的现行文档。调工具前的固定受理尚未实现。

## 验收任务

2026-09-25 由用户确认。每句都是用户会对她说的原话；每个阶段的退出条件引用其中的编号。

跑法参照 Hamel Husain 的 [AI Evals FAQ](https://hamel.dev/blog/posts/evals-faq/)，先做失败分析，再建自动检查：

- 用户是唯一裁判。每次运行只判通过或不通过，不打分。
- 先读真实运行，用自己的话写下哪里不对；读够了再把这些笔记归成几类失败。不预先写评分标准，不为想象中的错误写检查。
- 每句换说法、换页面、换应用状态，凑到每类失败不再出新花样为止（经验值约 30 到 100 次运行）。
- 只给反复出现的失败建自动检查；通过率接近 100% 说明题太简单。

| # | 用户说的话 | 场景 |
| --- | --- | --- |
| 1 | 「把这个问题拿去问 ChatGPT，答案读给我」 | 调用其他 AI 工具 |
| 2 | 「把我屏幕上这个报错拿去问 ChatGPT」 | 调用其他 AI 工具 + 屏幕理解 |
| 3 | 「让 Claude Code 把这个 bug 修了，改完告诉我」 | 调用其他 AI 工具 |
| 4 | 「Claude Code 跑完了叫我」 | 盯进度 |
| 5 | 「这个页面讲了什么」 | 浏览器只读 |
| 6 | 「查一下 X 最近的进展，整理成一页笔记」 | 浏览器整段工作 |
| 7 | 「把这 20 个公司的官网和价格整理成表格」 | 浏览器批量 |
| 8 | 「把这份资料填进这个网页表单」（提交前问用户） | 浏览器写入 |
| 9 | 「这个群今天说了什么，有没有人 @ 我」 | 微信只读 |
| 10 | 隔天问：「昨天让 Claude Code 修的那个怎么样了」 | 记忆 + 延续 |

## 界面分两层

- 系统级状态界面（现在做）：`ThinkingOrb` 状态指示、字幕、任务进度；低噪音，不占屏幕中央。
- 角色形象（以后）：只在需要表达情绪、等待确认、递出结果时出现；服务于操作，不盖过系统状态。

## 记忆原则

- 只记会改变未来行为的东西；每条有来源、时间和用途。
- 来源（2026-09-25）：用户顺手交给她的案例；她自己看浏览和屏幕；读用户的项目和 Claude Code、Codex 会话记录。
- 用户可见、可直接改的一个位置是唯一真相。她自己看来的内容不逐条审核，但都放在这个位置，用户随时能看、能改、能删。
- 截图可以保留，只存本机，占用有上限。
- 用户说"忘掉"时删干净，截图与摘要一起删；删不干净就明确报错。
- 不保存原始麦克风音频。

## 主动提醒与唤醒词

- 主动提醒只由真实变化触发，而且要少。不说话也是一种经过判断的选择。
- 长期监听必须先由本地唤醒词守门，被唤醒后才进入实时语音；快捷键始终保留。

## 竞品是参考

Her 是个人工具，不和竞品比差异（2026-09-25）。竞品是参考来源：好的做法拿来用，不需要证明比谁强。
「全双工语音 + 本机操作 + 有记忆的人格」早已有人在做；中文、有名字、有记忆、会主动的 Today AI 就是一例。
Today AI 除云端电脑外还有本机原生宿主：2026-09-24 复核 1.19.5 样本，`today-mac-platform-host` 链接 ScreenCaptureKit、ApplicationServices、AVFAudio、Contacts、EventKit（只证明它有本地能力，不证明效果）。Incredible 有桌面辅助进程和浏览器扩展（见 `docs/research/incredible-reconstruction.md`）。
质量目标（不是竞争说法）：同样的日常任务上，用户需要解释、监督和纠错的次数更少，而且她从不虚报完成。
不去拼的：应用集成的数量（只接用户真正用到的应用）、语音模型本身。阶跃既是供应商也扶持竞品（Today AI、小跃），语音接入保持可替换。

## 推进顺序

阶段、退出条件和当前状态见 `docs/ROADMAP.md`（2026-09-23 起取代此处原有的五步列表）。
每一步都要交付一个用户能感受到的变化。验收基建够用即可，不再先于产品面扩张。

## 本阶段不做

云端电脑、第二个推理运行时（Node/Python sidecar、Pi、Hermes、OpenClaw）、手机端、插件市场、公开分发与公证、企业和团队功能。
浏览器扩展不算第二个运行时：它只负责感知和执行，决策留在 Her（见 `docs/ROADMAP.md` 目标架构）。被她调用的 Claude Code、Codex 等命令行工具也不算（2026-09-25）。
