# Today 为什么能主动说中用户在意的事

2026-09-26。用户要求继续落实 Her 的真实委派流程，同时研究 Today 主动消息的吸引力。本次「Chat AI」暂按此前连续讨论的 Today AI 理解。

## 判断

最值得学的是把变化联系到这个人的具体事情，而非在通用聊天模型外加定时器。兴趣不只有主题，还有关系：这是我报的问题、我正在做的项目、我使用的工具、我还没决定的事。

这是界面样本与官方说明共同支持的推论，不是已经逆向出私有推荐算法。用户说消息普遍感兴趣，是用户体验判断；本轮没有足够样本证明通知精确率或因果关系。

## 本轮真实观察

通过原生电脑控制只读查看首页、任务/定时任务入口、Interests/ai-tools 记忆，再返回首页。没有发送消息、创建任务、修改记忆/设置或新增连接。以下不复制邮件、账单和其他私人细节。

| 实际消息 | 与用户的联系 | 可借鉴之处 |
| --- | --- | --- |
| 用户提交的 browser-control issue 收到维护者回复 | 本人参与，仍有待验证事项 | 给出验证条件、范围限制和可选择的下一步 |
| Supabase 权限变更提醒 | 使用相关基础设施 | 将变化翻译成可能影响项目的后果；本轮未核实变更本身 |
| Coding Agent 比赛信息 | 与正在做的方向有关 | 在已有兴趣附近发现机会，不只提醒待办；未核实赛制 |
| AI 产品发布/订阅传闻 | 与正在使用的工具组合有关 | 新闻关联个人选择；标注传闻不代表已证实 |
| 周末工作与休息两条选项 | 同时考虑项目与生活 | 让用户决定，不把所有兴趣变成待办 |

实际记忆页将工具使用与技术兴趣分组，标注 Gmail、GitHub starred 等来源类别。技术兴趣细到 computer-use、Agent 编排和 Coding Agent 工作流。这证明存在比「喜欢 AI」更具体的材料，不证明某条消息调用了哪条记忆，也不证明记忆全都最新、准确。

## 反例：有吸引力仍可能说错

9:59 晨报把 trycua/cua #4051 标为「已合并」，13:18 主动聊天却明确说仍为 draft，仅覆盖部分 AppleScript 分派问题。

本轮独立读取 [GitHub PR](https://github.com/trycua/cua/pull/4051) 与公开 API：`state=open`、`draft=true`、`merged=false`、`merged_at=null`。晨报的合并声明没有来源支持。稍后的审慎消息也不能自动修正仍展示旧结论的卡片。

晨晚重复出现同一存储问题与比赛，可能是未决事项跟进，也可能是去重或同步不足。没有触发日志，不能断言原因。

Her 应分别判断：与用户相关吗、事实成立吗、现在值得提示吗。三项不能合成一句「模型觉得重要」。

## Her 的借鉴方案（未实现）

```text
来源变化或新材料
  -> 与哪个项目、兴趣或未决事项有关？有何证据？
  -> 相比已经知道的内容，新增了什么？
  -> 事实与时间是否核实？是否只是传闻？
  -> 现在提示有价值，还是留待回来再看？
  -> 说明变化、为何相关，保留来源与可选下一步
```

- 同时保留跟进旧事和发现新东西。好动效、好文章即使没有待办也有价值，不把伙伴做成催任务的软件。
- 推荐与历史回忆分开，不冒充用户以前见过新推荐。
- 优先使用明确的项目/参与关系、用户提供的材料及已授权来源；本次研究不授权全盘监控。
- 兴趣、当前目标、未决事项分别保存；已解决、已放弃、不想再看的内容不持续施压。
- 没打开、晚点、不感兴趣、判断错了是不同反馈；沉默不等于没有兴趣，点击率不等于有帮助。
- 同一事项更新当前状态，并保留来源与核验时间，避免简报与聊天互相矛盾。

最小验证建议：用一组有来源的真实候选，比较泛主题推荐和联系具体项目/未决事项的消息；保留用户想看的新发现，也检查应保持安静的反例。这是离线产品实验，不是已开启的自动通知系统。

## 与当前开发的关系

主动消息以后也应回到原任务或来源。因此本轮仍先落实已批准的原生委派场景：确认项目、发送、收起、返回真实结果与待决定事项。这提供可靠的任务事实，但不等于已经实现长期记忆或主动推荐。
