# 桌面伙伴二次开发方案

日期：2026-09-20。历史设计与阶段记录。
2026-09-21 的任务约束、语音播报和续接实现以
[可信桌面控制方案及验收](development/2026-09-21-trustworthy-desktop-control.md) 为准。
下方六动作自由循环等阶段记录不代表当前接口；早期单次点击成功也不覆盖后来失败的场景。

## 目标与首版范围

让用户少解释、少确认，同时理解正确并真正完成任务。

首版支持在一次明确开启屏幕访问的会话中，共同看当前页面、连续追问、换页比较，
以及完成眼前的短操作任务。用户无需为任务中的每一次点击重新发指令。
保留文字入口、本地目标识别与共享执行引擎。

暂不扩展长期个人记忆、后台自主工作、教程生成、复杂跨应用长任务。
这些是本阶段范围，不是永久产品限制。模型供应商不决定用户入口或产品能力边界。

## 已有证据与尚未完成的事

- 用户确认实际屏幕回答基本准确；这是单次会话证据，不代表持续跟随已通过。
- 实测视觉分析约 3.3–12.4 秒；不是完整语音响应耗时。
- 中文 OCR 缺失与 OCR/YOLO 重复目标已修复并通过针对性测试。
  最后更新后的真实点击仍未验收，不能写成已经完成。
- 用户报告同一次会话音色变化，原因尚未定位。
- 语音生命周期测试证明部分取消和播放规则；不证明实际操作正确、音色稳定。
- 不沿用“视觉模型永远不能定位”的旧结论。既有文档已撤回坐标协议误读；
  本方案暂时复用本地定位，是基于现有可用结构，不是断言其他路线不可行。

详见 [点击排查](development/2026-09-20-voice-click.md) 与
[语音验收的历史更正](voice-rebuild-acceptance.md)。

## 交互规则

| 情况 | 应有行为 |
| --- | --- |
| 询问当前文章、图片或图表 | 按问题取得当前视觉内容，回答具体信息 |
| 要求点击一个名称明确的可见控件 | 用新鲜本地候选直接定位执行；不强制先生成整屏描述 |
| 要求点击“左侧那个带三的任务” | 继承已经说明的名称、位置、应用；不得把澄清信息丢掉 |
| 标签不足以区分目标 | 先结合位置与已有上下文；仍有真实歧义时，询问缺失的那一点，必要时提供可指向的目标 |
| 用户说“刚才那个” | 查本次会话中与讨论相关的历史观察，不把旧画面当成当前画面 |
| 目标没找到或观察过时 | 在同一任务内做一次受限的重新观察；仍失败则说明具体原因，不无限循环确认 |
| 动作执行成功 | 检查目标状态或预期结果后报告完成 |
| 只生成了“我来操作”的话 | 任务仍为待执行，不能报告成功 |
| 用户明确停止 | 撤销待执行动作及旧输出；已经发生的动作如实保留，不宣称自动撤销 |

本地重新观察不能扩大用户授权。发送、删除等后果较大的操作仍按明确授权处理；
普通已授权可撤销操作不新增泛化确认。

## 模型分工与调度

根据 [Cua 的 System One 文章](https://x.com/trycua/status/2101437979180904640)，
本草案补充“何时进入局部决策、何时返回开放推理”的边界。以下 Realtime 分工
是结合本项目需求提出的设计，不是该文章已验证的语音架构。

| 角色 | 使用条件与职责 | 不应承担的职责 |
| --- | --- | --- |
| 程序规则 | 已有唯一、有效目标；权限、重复检测、状态有效期、取消、执行和可确定的结果检查 | 不用关键词规则猜测复杂用户意图 |
| Realtime Voice Agent | 听说、普通交流、理解简单意图与指代、接收纠正和解释执行结果；提交带上下文的任务 | 不独自掌管第二份任务状态，不以口头承诺代替动作，也不在缺少证据时声称看到了画面 |
| 通用推理/视觉模型 | 理解复杂内容、生成文字、规划陌生步骤、解释异常和重新规划；视觉问题使用支持图像的能力 | 不为每个已明确的按钮重复做整屏推理，不重复询问已获得的限定 |
| JEV | 目标与状态充分，程序已经构造出有限候选，但选择仍需语义判断；选动作、匹配目标或辅助判断局部条件 | 不生成缺失内容，不补造控件、坐标或参数，不负责陌生流程规划；概率不替代执行验证 |

这是职责划分，不是必须部署三个模型或逐个调用的流水线。Realtime 若经实测可可靠
承担某类通用推理，可以兼任；JEV 也不是所有点击的必经节点。首版不新建一个只负责
“选择模型”的模型服务：已有明确工具请求和任务状态先由程序分派，复杂语义交主 Agent。

### 三条实际路径

1. “点击左侧带三的任务”：Realtime 理解指令 → 当前本地候选 → 唯一明确目标由程序
   校验执行；需要语义选择才调用 JEV → 检查结果 → Realtime 简短反馈。
   不强制调用视觉模型和通用规划器。理解了语句不等于目标已唯一，不能省掉定位检查。
2. “这张图表达什么，和刚才那张有什么区别”：Realtime 携带问题和会话上下文 →
   通用视觉理解 → 回答。无操作要求时不调用 JEV 或执行引擎。
3. “打开这个应用的显示设置并找到缩放选项”：通用 Agent 规划当前短任务 →
   对每个已界定步骤构造候选 → 必要时 JEV 选择 → 程序执行与检查。
   出现意外弹窗或检查失败时交回通用 Agent，携带失败事实继续判断；用户不必重述任务。

### 交接必须保留的内容

通用 Agent 交出明确子目标、已有用户限定、允许动作、所需值的来源和预期结果。
候选由程序绑定到当前观察：候选 ID、目标 ID、应用/窗口、动作类型、完整参数、
观察版本和适用条件。JEV 选择候选 ID；程序回查原候选并验证后执行，不能让模型
补全参数。用户提供或通用模型生成的文字进入候选前，必须保留来源和适用授权。
局部选择保留“重新观察”和“无合适动作”的出口，不强迫从错误候选中挑一个。
视觉候选绑定其对应截图/观察身份，失效后不能降级成无身份的坐标点击来绕过拒绝。

目标缺失、状态过期先重新观察一次；新状态仍不足、出现未覆盖弹窗、动作失败、结果
不符合预期或局部预算耗尽，则停止该局部循环，交回主 Agent。交接包保留当前目标、
用户澄清、最新观察、已执行动作及失败原因，不仅返回一句“失败”。主 Agent 在剩余
任务预算内恢复；仍缺少用户才能提供的信息时才提问。禁止 planner 与 JEV 无界互相重试。
如果请求超时但动作是否发生不确定，先读取实际状态再决定是否重试，避免重复执行。

高分不能覆盖候选遗漏、错误标签、状态过期或失败检查；低分也不能自动变成向用户
再问一遍。首版不改变现有 JEV 概率门槛策略，不凭文章增设任意置信度阈值。是否升级
由上述可观察条件决定，概率作为辅助证据记录。

## 工程职责

### 1. 屏幕上下文：当前证据

保留现有感知和 TipTourEngine，补齐统一观察身份：应用/窗口、捕获时间、版本、
本地文字与目标、按需获得的视觉内容。每个目标保留本地 ID、位置和所属观察。

两条路径共享观察：

- 内容问题：问题 + 当前画面 → 视觉理解 → 对话回答。
- 明确操作：任务 + 当前候选 → 目标选择 → 共享执行引擎 → 结果检查。

视觉理解只在当前信息不足时加入操作路径。明确标签的点击不必经过整屏视觉描述。
会话期间监测窗口/页面变化；变化先使旧观察失效，画面稳定后按需更新。
不要把每一帧都发给模型，也不要让慢速旧观察覆盖已经更新的画面。

### 2. 会话上下文：当前目标和用户已说明的信息

在现有协调器中明确一份会话上下文，先不引入新数据库或长期记忆服务：

- 当前讨论/操作目标、用户已经给出的限定、尚缺的信息。
- 当前观察与少量和讨论相关的历史观察；旧观察带来源和时间。
- 任务状态：待定位、待澄清、执行中、已完成、失败、已取消。
- 工具调用和实际动作结果，与同一个任务身份关联。

最近对话保留原文，较早的相关内容按需摘要。屏幕事实会过时，用户偏好与目标
有不同寿命；不能把所有内容压成一个无时间标记的“记忆”。停止会话后停止观察，
下一次会话默认重新建立屏幕状态。本阶段不承诺跨会话回忆。

### 3. 执行：一次目标选择贯穿动作

复用 WorkflowRunner → ActionExecutor/TipTourActionDriver 的路径，不旁路权限、取消和检查。
JEV 可在程序定义的候选动作中选择；已唯一确定的有效目标可直接进入共享执行引擎，
不再退化为纯标签后让第二个模型重选。
目标随界面变化时，通过现有连续性匹配或重新定位确认，不能直接使用陈旧坐标。

一条用户任务可包含受限的连续步骤，预算由程序控制；每一步后检查状态。
允许表达与动作并行，但动作是否完成只由结果决定。语音模型没有继续调用工具，
应留下明确的待执行/失败状态，而不是悄悄把这轮当作成功结束。

### 4. 语音：表达和可打断性

音频连接、响应生成、扬声器播放、任务执行分别管理，继续使用现有运行身份隔离迟到事件。
普通插话先停止旧播报并暂停尚未下发的动作，结合新话语决定继续、修改或取消原任务；
明确“停止”立即取消。不得把每次开始说话都解释为放弃整个用户目标，也不得在用户
纠正目标后继续执行原目标。

音色以实际听感验收；配置中的 voice ID 相同不算通过。

## 语音选型：有限验证后再决定

| 路线 | 保留的优势 | 必须验证的代价 |
| --- | --- | --- |
| A：现有实时语音 + 按需通用推理/视觉及局部执行 | 复用较多，原生连续听说 | 直接执行、局部决策与开放推理能否正确交接，视觉等待期间是否丢任务、音色是否稳定 |
| B：语音识别 + 支持视觉/工具的主模型 + 固定 TTS | 任务控制与声音分别管理 | 串联等待、流式播报、插话与任务暂停能否达到体验要求 |

先确认非语音候选构造与执行检查在受控页面成立，再做隔离语音小样；不能把缺失目标
和执行器故障算成语音模型能力差异。不同时重写两套主工程。共用相同的任务状态和执行契约、测试页面、
问题和输出要求；两条路线都不能靠删掉屏幕理解或改成半双工来取得速度优势。
供应商及模型根据可用接口和实测选，尚未决定更换阶跃，也不假设另一条路线必然更快。

两条路线都通过时，优先保留改动更少的 A；如果 A 持续丢动作或音色不稳，而 B
能稳定完成并且等待可接受，再选择 B。若两条都失败，缩小并修正具体瓶颈，不扩建主工程。

## 验收与证据

先由开发代理在可撤销的受控页面完成链路验证，再交用户做真实中文语音与听感验收。
不再把每个内部小修都交给用户重新试；一次交付覆盖完整场景。
受控页面提供独立的结果读回，例如实际选中的条目或字段最终值；不能只检查 Driver
返回成功、模型自报完成或 AX 树发生变化。mock、真实模型及真人语音的证据分别记录。

| 场景 | 可观察的通过条件 |
| --- | --- |
| 读页面后追问第二点 | 引用当前页面具体内容，追问不要求重述全文 |
| 换页后与上一页比较 | 识别页面已变化，正确区分当前与历史内容 |
| 指定中文任务名和位置后点击 | 点击正确对象，不因同一控件的重复检测反复确认 |
| 完成需要展开菜单再点击的短任务 | 一次指令连续完成，最终页面/状态正确 |
| 真正不同位置的同名控件 | 缺少限定时询问；得到限定后执行，不重复问同一问题 |
| 唯一目标、语义候选选择、复杂视觉问题 | 分别验证程序直达、JEV 局部决策、通用视觉路径；不让三类模型一律串行 |
| 候选缺失或突发弹窗 | 停止局部循环，带完整上下文返回主 Agent；不靠高分猜点，不要求重述整个任务 |
| 视觉请求期间换页、执行中纠正目标或停止 | 不把旧结果当当前事实，不在取消后产生旧动作 |
| 同一次会话连续对话及工具返回后回复 | 声音身份保持一致，不自行截断或重复播报 |

先各跑一次定位结构性失败；修正后同组场景重复三轮检查稳定性。小样结果不作为总体成功率承诺。

每次记录：用户说完时间、请求被理解、观察完成、动作下发、可见结果、第一句有用回复、
实际播放结束。记录实际调用的模型、调用次数、升级原因和交接耗时，报告各阶段中位数与范围、错误动作、无效确认、未执行和虚报完成。
“好的，我看看”等填充话语不计有用回复；模型决策耗时不冒充完整操作延迟。

误点、取消后继续动作、虚报完成任一出现，相关场景不通过。对等待和音色，开发记录
客观时间/音频现象，用户保留最终体验判断；不编造未经确认的满意度或延迟门槛。
原 JEV 文字入口和已有停止行为也必须保持可用。

## 实施顺序与边界

1. 评审本草案，确定交互规则和首版范围。
2. 确认受控候选与执行检查有效，再以相同场景进行隔离语音路线验证，给出证据和选型结论，不新增生产接口。
3. 选型后，按“明确指令到实际动作”的完整路径实现，再补齐连续屏幕上下文。
4. 同一构建完成上述场景验收，再交用户体验，不以测试数量或构建代替完成。

此前修复保持现状；本文件不授权提交、发布、删除已有实现或扩大权限。

## 2026-09-20 实施与当前验收

用户指定主代理直接执行。现有实时语音路线已接入独立桌面任务状态、最多六次动作、
精确目标执行、可选 JEV 决策及通用推理恢复；读屏保留最近四次观察，窗口变化使旧编号失效。
中文 OCR、重复候选、非当前窗口误触发弹窗拦截及网页动作后验证深度已修复。

当前构建已通过 Xcode，正在本机运行。用户已确认“可以正常点击了”；对应真实语音日志
显示 `act_on_screen` 选择“检查官网部署状态（3）”，执行器下发点击，工作流完成，
任务结果为 `completed`、一次动作。此项通过，不重复要求用户测试。

按用户最新要求，后续真实体验由用户直接测试，代理检查日志，失败再定位，不机械重复三轮。
尚待验收：两步操作、读屏追问与换页比较、读屏或操作期间打断、连续会话音色。
