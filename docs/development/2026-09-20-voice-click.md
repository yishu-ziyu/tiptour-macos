# 阶跃语音点击排查

## 实际路径与证据

- 用户要求点击 Codex 左侧置顶的“检查官网部署状态（3）”。旧运行日志只出现
  `describe_screen`，没有 `act_on_screen`；这不能证明底层动作引擎失败。
- 当前构建包含屏幕视觉接入，用户确认屏幕回答基本准确。观察到视觉请求耗时
  3.3–12.4 秒；这是视觉环节耗时，不是完整语音等待时间。
- 本地 OCR 仅配置 `en-US`。真实 OCR 回归图的中文、繁体中文标题完全缺失，
  英文标题正常；加入 `zh-Hans`、`zh-Hant` 后三个标题均识别成功。
- 第一次更新后，真实语音日志已出现中文候选与 `act_on_screen`。
  但同一标题分别作为 `[text]` 与 `[element]` 出现，触发同名拒绝。
  用户进一步说明位置后，旧描述又因 20 秒有效期过期而拒绝。

## 本次修改

- 本地 OCR 同时识别简体中文、繁体中文和英文。
- 候选列表合并名称相同、来自不同检测源且高度相近、区域高度重合的结果；
  保留原来的来源优先级。不同位置的同名控件和较大的父区域仍保留。
- 语音编号映射到 JEV 后，任务明确为“点击控件”，不只传控件名称。
- Debug 构建记录完整工具返回和完成的语音转写，便于区分目标缺失、动作拒绝
  与模型未继续调用；Release 不输出这两类调试正文。
