## 目的地

[阶段 4：调用其他 AI 工具](../ROADMAP.md) 的最小版本：用户在 Ctrl+K 里和她说要改什么，她边聊边把要求攒完整，给用户看一眼要交出去的内容，用户确认后经命令行交给 Claude Code，在当前项目的一个单独 git 工作区里执行；用户交给她的案例放在本机，Claude Code 需要时自己去查；跑完后她如实汇报改了什么并附上差异，用户同意后再合并。（2026-09-25 参考开源项目后修订，见 [delegation-references.md](../research/delegation-references.md)）

怎样算做到（可证伪，由用户在真实构建上判定）：

- 用户自选至少 3 个真实改动请求，每次只判通过或不通过，并用自己的话写下哪里不对。
- 她汇报的「改了什么」与仓库的独立读回（`git diff`/`git status`）一致；Claude Code 失败、中断或没改动时，她不说做成了。
- 用户在交出去之前看到、并确认过要发的内容。
- 用户自己工作目录里没提交的改动不被碰到；合并只在用户同意后发生。
- 她工作期间用户的鼠标键盘不被占用。
