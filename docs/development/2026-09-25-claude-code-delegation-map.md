## 目的地

[阶段 4：调用其他 AI 工具](../ROADMAP.md) 的最小版本：用户在 Ctrl+K 文字入口说一句「让 Claude Code 把……改了」，她把用户的原话、用户最近在做的事、用户交给她的相关案例和当前屏幕截图打成一个上下文包，经命令行交给 Claude Code；Claude Code 自己展开成计划并执行；跑完后她如实汇报改了什么，并把交出去的上下文包一起给用户看。

怎样算做到（可证伪，由用户在真实构建上判定）：

- 用户自选至少 3 个真实改动请求，每次只判通过或不通过，并用自己的话写下哪里不对。
- 她汇报的「改了什么」与仓库的独立读回（`git diff`/`git status`）一致；Claude Code 失败、中断或没改动时，她不说做成了。
- 用户能看到这次交出去的上下文包全文。
- 她工作期间用户的鼠标键盘不被占用。

## 还没弄清的

设计这一段时由 agent 查事实、给推荐，用户做决定：

- 她怎样调用 Claude Code：无头命令行的调用方式、权限模式、工作目录、超时与取消；用订阅自动调用的使用条款。
- 这条命令行路径与 `CompanionManager` → `TipTourEngine` 链的关系：新的执行器，还是走现有引擎。
- 「当前项目」怎么确定：前台窗口所在的仓库、用户指定，还是最近活跃的仓库。
- 「最近在做什么」从哪些文字来源拼出（提交记录、当前地图、Claude Code / Codex 会话记录），取多少。
- 用户交给她的案例存在哪、什么格式；截图存在哪、上限多少。
- 这一段先用哪几个真实请求验收（用户选）。
- Codex 什么时候接：本段内，还是本段通过之后。
