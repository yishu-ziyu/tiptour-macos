# Her 路线图

现行文档，2026-09-23 建立。产品准则和价值函数见 `docs/PRODUCT.md`；旧仓库的来源与迁移清单见 `docs/lineage.md`；竞品架构证据见 `docs/research/incredible-reconstruction.md`。
每个阶段都要交付一个用户能感受到的变化，并有可运行的退出条件。状态只写有证据的事实。

## 目标架构

```
                    用户（语音 / 快捷键 / 以后的唤醒词）
                                   │
                    ┌──────────────▼──────────────┐
                    │     Her.app（Swift，唯一大脑）  │
                    │  语音会话 · 人格 · 记忆 · 技能   │
                    │  任务协调 · 回执 · 确认 · 验证   │
                    └───┬──────────────┬───────────┘
          桌面操作        │              │  Chrome 扩展（本机 WebSocket，Origin 认证）
  AX / OCR / YOLO 感知   │              │
  WorkflowRunner → CUA                            │     ┌────────▼─────────┐
                         │     │  Her 浏览器扩展   │  在本仓库新建，设计参照研究文档
                         │     │ 只做控制面：DOM   │  CDP 用最小集合；标签页归属；
                         │     │ 读取、CDP 输入、  │  可见光标与任务卡；教学录制
                         │     │ 截图、教学录制    │
                         │     └──────────────────┘
                   阶跃实时语音 / 视觉；TypeSafe JEV（可选）
```

原则：整个系统只有 Her 一个大脑。扩展和辅助进程只负责感知和执行，不做决策；不引入第二个推理运行时。这个结构与 Incredible 已验证、并通过商店审核的做法一致（桌面中心 + 本机 WebSocket + 只做控制面的扩展），证据见研究文档。

- 阶段 2 与阶段 3 并行推进；两者完成后做阶段 4，再按表中顺序推进。（2026-09-23 晚，用户指出首次使用、引导和美学不够好后调整；取代「阶段 2 收尾后先做记忆」。）
